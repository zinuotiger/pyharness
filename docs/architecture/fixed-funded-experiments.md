## 问题与结果

同一份回归资料需要在两个已发布 Agent 版本上执行，并将实际执行、有限断言质量和独立业务验收分别报告。保存 Case、Dataset 或实验定义本身不授予执行权限。原任务图已有严格的原始任务队列、预算、固定配置、权限边界和停止流程，因此实验复用这套机制。

## 固定资料与准备

一个定义绑定精确 DatasetReference、显式选择的 1–10 个 CaseReference 和两个不同的发布版本引用。Dataset 本身仍最多 32 例；界面与报告显示 dataset_total、selected_count、excluded_count，不会静默截断。每例通过原 ProductTask 命令创建一项正式任务，objective 是操作者确认过的 Case.input_text，input_binding 取自原来源执行固定的输入，资料与引用沿用精确引用，旧交付定义不会冒充新任务交付定义。

每对节点共享相同正式任务、文档和引文引用，各用一个发布版本，没有依赖边。原图 20 节点、4 并发上限保持。准备先保存不可变 preparation 意图，再通过原 ProductTask/TaskGraph 保存命令创建数据，最后保存实验定义。它不是多资源原子事务；回执丢失时沿原提交键查询、核对精确已保存任务并继续准备，不删除历史或换键盲重发。准备不创建运行队列或调用模型。

历史观察读取原不可变发布快照并核对SHA；版本退役不会抹除已授权可读的旧报告。新的准备、预算编译与恢复仍使用原new_binding_version门，退役版本不能获得新执行权限。主体、资料和现行保密规则在两类操作中都必须通过。

## 一份预算只绑定一次原图运行

运行预览绑定实验运行 ID、精确实验定义、原图编译后的节点清单、配置指纹、边界和四维预算。budget_grant 必填，四个维度都必须覆盖发布 Agent 的实际分配，且不能超过定义限额。预览按原模型价格与边界检查，没有客户端自报 scripted 豁免。原 task_graph_run 使用既有 512 KiB 上限；新增 funding 记录使用 32 KiB 上限，预览先核对序列化容量。

先把 funding 记入原控制日志，只有第一次确认保存成功后才调用原 start_task_graph。派生的原图运行 ID 和原图请求键固定，禁止其他请求把该 ID 绑定到不同命令。历史和最小停止投影均验证 funding 与原图的所有权、精确命令、时序、分配预算和节点清单。

同 funding 键重投只观察，不重新派发；冷启动查询与原键核对不会重建 GraphOwner、TaskQueue 或 Engine。若 funding 已登记、原图尚不存在，则显示 registered_not_dispatched。只有明确的恢复预览与确认、健康写入器、未取消且编译配置仍一致时，才沿同一个原图 ID/原图键继续。原图已登记的冷运行只观察，不能根据未知效果重新执行。

## 最小停止控制

实验运行与实验取消进入原有、只减少权限的控制投影。停止不读取 Case、文档正文或宿主源目录；资料撤权、项目归档之后，同一主体仍可查询最小停止引用并请求停止。运行、恢复与取消共用实验准入锁。

运行目录同样使用最小控制投影，因此正文blob丢失也不会阻塞查找同主体停止目标。归档项目的实验入口保留，只展示最小运行控制，不重新开放准备、执行或报告。停止写入失败或回执未确认时，仅在完整实验Ref、原图Ref和当前主体均核实后，对原GraphOwner及确切队列发送减少权限的信号；原响应仍失败，不宣称记录已经提交或外部效果已撤销。

先保存实验取消意图，再调用原 cancel_task_graph。原 GraphOwner 也直接检查该实验停止意图，覆盖取消意图已保存、原图取消尚未保存的窗口。不改变旧 _graph_cancelled 的定义，避免原取消入口拒绝自身正常控制记录。取消回执只声明请求已保存，execution_stopped 保持未确认，实际结果由原运行事实核对。

## 报告的固定事实与三个分母

报告固定原控制日志前缀，以及每个根执行日志和已授权子日志的物理 session_id、seq、规范字节 SHA-256。保存时服务端按这些精确前缀重算，客户端不能直接提交评分结果。读取旧报告仍按旧前缀重算，后续日志尾部、新 Case 修订或新验收不会替换旧报告的观察点。

有限检查器沿用 regression-assertions-v1，同时记录实际 regression_assertions.py 字节摘要。检查器实现变化使重算明确不可用，不让今日实现悄悄替换旧实现。历史结构校验与当前隐私/主体/来源权限分开；每次实际读取前后重新检查当前权限。报告有节点、断言、子日志、聚合扫描体积、事件数、总字节和观察时间上限，超限拒绝，不静默省略。

报告分别统计：

| 维度 | 分母与计数 | 不允许的归并 |
|---|---|---|
| 实际执行 | 节点总数及 completed/failed/cancelled/unknown/interrupted/not_dispatched/nonterminal | 未派发或效果未知不能算执行完成 |
| 有限质量 | 节点总数、可评数、passed/failed/unknown | 缺失、屏蔽、裁剪或不完整答案不能当完整答案通过 |
| 独立业务验收 | 节点总数、已评数、accepted/rejected/invalidated/not_evaluated | 测试通过不等于独立业务通过 |

实验有单独的输入对齐证明：相同正式任务、输入绑定、资料/引文、交付引用和声明输出模式，且没有改写输入历史的纠偏。它不会把原通用比较器对 schema 3 的“不具备对齐证明”强行改成可比。声明验证器或实际输入不一致时可显示描述性检查结果，但不输出硬回归归因。

用量沿原 llm.request/llm.usage 配对事实计算；缺请求、输入计数或价格时保留未知，不能将脚本替身的 usage 记录补造成真实传输事实或零费用。

nonterminal 表示固定日志前缀尚未记录终态，不宣称当前物理进程仍在运行，也不会把取证时仍在进行的任务冒记为中断。后续合法日志先由当前授权的原读取器验证，再裁到报告固定前缀；新的控制证明不会改变旧评分基准。读取原根/子日志之前核对合计物理文件 32 MiB 上限，评分前缀另有合计规范字节和事件数上限。

## 保存、导出与兼容

保存报告不导出、不发布。下载先单独预览，再核对确认摘要、当前权限、原规范字节 SHA 和现行秘密过滤。测试绿不自动发布 Agent 或 Release。

报告是关闭的严格结构，不含自由输入/输出正文。出口先按模型和原证据绑定核对，再仅在明确的摘要、会话和资源引用路径上用验证占位值作秘密扫描；其余完整规范结构仍经过现行规则。返回的始终是未替换的原规范字节及其 SHA。这样避免原 32 位疑似密钥规则误伤合法 SHA 和会话 ID，同时不放宽全局规则、不按字符串外观泛化白名单，也不允许额外自由文本混入。

原 90 个事件类型和 22 个同步事件不变。控制资源在 S13 的 32 种基础上增加 preparation、definition、run、cancellation、report 五种严格叶类型，即 37 种。公共审计资源类型与 ID 联合显式扩展；同时补齐 S13 遗漏的 Case/Dataset ID 模式，保留原字段与旧参数。新报告复用原有大上下文 blob 的 512 KiB 容量分支，报告数据自身另限 256 KiB。没有新增持久数据库、日志事件族、队列或执行引擎。
