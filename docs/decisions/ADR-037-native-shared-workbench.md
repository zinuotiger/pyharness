# ADR-037 原生控制与受权工作台共享服务

状态：Accepted（S18实施验收进行中） · 日期：2026-10-21 · 落点：S18双壳 · 原则：唯一执行权威、最小授权、生命周期归属。

## 背景

原生壳已有九个页签、会话与运行控制，Web壳承载完整产品业务。两个壳分别自建同根服务会产生并行会话门面、队列和日志所有者，不能作为共享状态接入。实际Windows DPR2基线还发现默认窗口框高于可用桌面，底部输入区受遮挡。

## 决策

原生端新增显式启用的完整工作台菜单。独立桥借用原生控制器的同一ApplicationServiceRegistry，在同一qasync事件循环启动仅监听127.0.0.1的HTTP服务，使用原FastAPI路由、账户、Host和Origin规则。DesktopApp默认注册表创建行为与构造签名保持；原生控制器继续只通过应用服务承载业务，不加入HTTP处理逻辑。

桥先绑定并持有随机端口socket，启动就绪限15秒；启动失败不复用载体。桥持有独立总线订阅owner，关闭仅摘自身订阅、关闭SSE、服务器与socket。服务关闭由原生控制器负责，关闭桥不建立或关闭另一套执行服务。正常关闭的有限等待与失败结果必须可见，不能把服务端监听关闭等同外部效果已撤销。

默认本机操作者沿用原引导令牌换HttpOnly Cookie。原生租户选择器不作为账户认证：非默认租户或已有账户上下文打开原登录页，不传宿主引导令牌。异步启动后重新核对当前服务、租户、主体与窗口存活；失效时不打开旧URL。

保留原九个页签与控件。首次显示及屏幕变化后，按实际可用桌面和窗口装饰计算尺寸。原生总线投影使用无额外等待的异步订阅，在所属事件循环调用Qt信号；避免同步订阅被线程池调度导致持久化前交错。窗口销毁或没有事件循环时关闭尚未启动的刷新协程，入口finally仍负责服务收尾。

## 后果

完整详情需要Web可选依赖；缺失时原生基础界面可启动，菜单提示依赖不足。仅打开网页不代表授权或执行任务，原审批与效果记录保持。浏览器关闭不关闭原生任务服务；原生程序退出会停止其自有HTTP服务。旧窗口最小尺寸仍受现有控件约束，实际设备与受限小屏的验收结果必须分别记录。

## 违反它的后果

新建同根服务会把原生启动与Web停止分离到不同队列，无法确认停止对象；线程池投影可在事件落盘前被取消和终态插入，造成序号缺口。给租户选择器附宿主令牌会绕开原账户边界。按全局desktop owner摘订阅会误停其他壳的观察通道。

## 备选方案对比

| 方案 | 结果 |
|---|---|
| 重写全部原生业务页 | 重复完整Web业务，扩大维护与回归面 |
| 独立线程或进程新建同根Web服务 | 不能共享非线程安全运行对象和队列所有权 |
| 同循环、同注册表受权详情桥 | 复用现有业务与身份边界，关闭归属明确；采纳 |

## 关联

沿用ADR-038产品控制日志、ADR-026执行效果、ADR-027恢复、ADR-036受控浏览器。该决策仅扩展S18双端接入，不取消旧租户/宿主执行边界，不把自动化输入当成人工物理输入证据。
