# Platform Web 开发候选：启动、账户与恢复

本说明对应十九项实施现场。完整验收状态见根目录 `PYHARNESS-IMPLEMENTATION-MATRIX.md`，不以旧版本 CI 代替当前结果。

## 启动

在独立虚拟环境安装候选 wheel 的 `web` extra，或在源码虚拟环境运行：

```powershell
python -B -m pyharness.web --data-dir <仓库外数据目录> --open-browser
```

`pyharness-web` 是同一入口。数据目录必须显式提供；默认随机端口，只绑定回环地址。可用 `--port` 指定端口。浏览器关闭不停止服务，使用启动终端的 Ctrl+C 正常停止。桌面 WebView 的旧入口保留原有“关窗退出”行为。

新目录不会继承全局模型配置、模型环境凭据、MCP 服务或插件。首次启动无可用模型，默认助手禁用代码执行。启动不会发起模型请求。操作者令牌由原有 DesktopApp 管理，以 HttpOnly Cookie 换取访问权限；入口不会把令牌打印到日志。

不使用 `--open-browser` 时，标准输出提供无令牌的团队登录地址。首次操作者管理请从本机用 `--open-browser` 进入；不要把数据目录中的操作者令牌发给团队成员。

## 账户、团队和模型

本地操作者在“设置 → 账户与团队”创建账户和团队。成员使用 `/login` 登录；团队管理员可以调整已有账户的 owner/member/viewer 权限或移除成员。加入多个团队后，在登录表单填写所选团队 ID；不能用租户请求头冒充团队身份。

密码使用随机盐和 scrypt；登录令牌在数据库中仅保存哈希，12 小时到期，注销立即撤销。角色在每次请求时重新读取，降级对现有登录生效。最后一个团队管理员不可被移除或降级。连续 5 次错误密码触发 15 分钟限制，登录哈希计算最多并行 4 个。

团队凭据存于既有租户 Secret 系统，不继承操作者模型。团队账户禁止使用宿主执行、宿主 MCP/插件管理及经典操作者界面；已有发布版本也必须经过该边界。原有本地操作者功能不删除。团队可以使用禁用执行的助手；isolated 是否可用由实际健康检查决定，不回退宿主。

当前 Web 入口配额：每团队 100 个会话、20 个交互活动 Run、上传产物合计 100 MiB。工作流另有最多 4 个并行编排、每个最多 20 步的上限；这些是应用层限额，不是 OS 级资源隔离或计费系统。取消操作不受“新建任务配额已满”阻断。

模型管理使用既有 OpenAI-compatible profile。用户点击测试前会提示可能产生少量费用；只做一次 64 输出 Token、60 秒超时的最小生成，无工具、重试和 fallback。结果不证明工具协议、完整 Agent 能力或模型质量；本轮自动验收全部使用合成响应。

## 后台任务和恢复

“设置 → 团队记忆”提供持久键值的读取、保存和删除，复用原有 SessionKV 存储。每团队最多 100 个键，每项值最多 4096 字符；禁止在这里保存密码、API Key 或其他 Secret。团队成员只读，团队管理员可修改。Agent 默认 `memory_scope: session`；需要跨会话共享时，发布定义显式选择 `memory_scope: team`，并按原有工具白名单允许 `storage.kv`。团队范围不会跨租户共享，损坏文件不会被当成空记忆覆盖。

“设置 → 定时任务”保留 Schedule，增加工作流入口。工作流顺序执行、失败即停，通过原有 TaskQueue 运行；重复提交的幂等键不会重复创建。状态从原有 SessionLog 恢复，不建立另一套任务数据库。未完成的进程中断显示失败，不自动重放可能产生副作用的步骤。

子任务成功、失败、取消与等待审批在聊天检查器可见。关闭通知只关闭父会话通知，不丢弃子任务自身的终态记录。并发子会话审批按完整会话身份路由。子任务失败不会使已发布 Agent 的父 Run 虚假成功。

## 停服备份和恢复

1. 正常停止服务，确认无运行任务和进程持有数据文件。
2. 把整个显式数据目录复制到受保护的本地备份位置，记录文件 SHA256。不要对活动 SQLite/事件文件做不一致的逐文件热备份。
3. 恢复前保留旧数据副本；用备份恢复到相同绝对路径，再以同一操作系统账户启动相同版本。
4. 检查登录、Session、Run、Approval、Trace、Artifact 内容及哈希。出现损坏时停止，不清空后假装恢复成功。

Windows Secret 使用系统账户相关的保护机制，跨机器/跨系统用户的凭据迁移未验证；本轮恢复测试仅使用合成数据且恢复到原路径。备份可能包含加密凭据和会话，不能上传到公开 CI 或作品集。此候选不宣称支持在线备份、断电原子性、跨机高可用或多进程共享服务。

## 交互式终端评估

Platform PTY 保持禁用。底层 `core/pty.py` 已有 ConPTY/POSIX PTY 实现，`proc` 的行式输入输出不是交互式终端。缺少平台会话所有权、实时输入、尺寸调整、断连与退出回收的一体化验证，是不开放入口的原因。

后续恢复前必须单独验证：授权会话绑定、非用户所属任务拒绝连接、真实 TTY 语义、受限 stdin/输出、窗口尺寸变化、断连与注销取消、父子进程回收、配额和敏感输出处理。不得用普通 shell 执行成功代替这些验收。

## 发布和环境边界

本地真实模型加 Docker 闭环仍待独立验收，保留现有实现和 fail-closed。GitHub 交付获准普通提交、推送和 Draft PR 更新，并执行原有正式 CI（含 Ubuntu 真实 Docker）。自动验收不调用真实模型、不读取用户凭据；不合并、不创建 tag/Release。

账户/租户是本地应用服务器的真实身份边界，并非公开互联网部署已经完成安全认证。部署到非回环网络、反向代理 TLS、外部身份提供方、跨机器凭据恢复及强对抗多租户沙盒需要独立验收；支付和营销系统不在本轮范围。
