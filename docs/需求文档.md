# Mini-Harness 需求文档(PRD)v0.1

> 文档顺序:本文件(需求)→ 架构设计.md(图纸)→ 代码
> 读者:许子诺(开发者本人 + 唯一使用者)
> 原则:先跑通,再严谨;砍掉一切不需要的

## 1. 项目背景:为什么做这个

### 1.1 一句话需求

做一个"会自己干活的小机器人框架"的缩小版,用 Python 复刻 DeepSeek Harness 最核心的架构思想。

### 1.2 动机(按重要性排序)

| # | 动机 | 说明 |
|---|------|------|
| 1 | 面试落地项目 | 面试官要"能讲清楚、能演示、证明你真懂 Agent"的项目。现有项目都是"用框架干活",这个是自己写框架的核 |
| 2 | 把 DSH 分析变成战绩 | 已完整分析 DSH 架构(9,044 文件),需要一个"亲手造出来"的产出,把"我懂"变成"我会" |
| 3 | 学习 Agent 骨架 | 通过自己写一遍,真正理解:循环怎么转、工具怎么调、日志怎么记 |
| 4 | 面试谈资 | "我拆了 DSH 全部代码,自己用 Python 写了个缩小版"——比其他候选人的"我用过 LangGraph"高一个层次 |

### 1.3 目标用户

只有一个人:**许子诺本人**。使用场景:
- 学习(写的过程中理解 Agent 框架)
- 面试演示(跑一个真实任务,录屏给面试官看)

**不是**给其他人用的产品,不需要安装包、不需要文档站、不需要多用户。

---

## 2. 项目范围:要什么 / 不要什么

### 2.1 要做的(核心三件套)

1. **Agent 循环(大脑)**:反复调 LLM,直到 AI 认为任务完成
2. **工具系统(手)**:工具注册、参数校验、危险拦截、执行、结果检查
3. **会话日志(本子)**:每一步只追加记录到文件,可回放、可恢复

### 2.2 明确不做的(砍掉清单)

| 不做 | 为什么砍 |
|---|---|
| 插件系统 | DSH 的 Cordis 是 2,693 行 TS,学习价值低,砍 |
| 上下文压缩 compaction | 外围功能,学习版不需要 |
| 子 Agent | 外围功能 |
| Web UI / 网页端 | 演示用录屏/命令行就够 |
| 多用户/多会话管理 | 单人单会话 |
| Python SDK / 给别人用的 API | 不是产品 |
| TS / Node 生态 | 全程 Python,不碰 TS |

**判断标准:凡是"去掉它,核心循环照样转"的东西,一律不做。**

## 3. 核心场景(验收时跑的就是它)

### 3.1 演示场景一:查天气给建议(第 1-3 步用)

```
用户:广州明天适合跑步吗?
机器人:调 get_weather 查广州明天天气
     → 32 度,有雨
     → "不适合,有雨,建议改室内"
```

### 3.2 演示场景二:整理文件夹(最终验收,录屏用)

```
用户:帮我整理 D:\杂乱文件夹 里的笔记,按主题归类
机器人:自己规划 → 列文件(调工具)→ 读内容(调工具)
     → 归类 → 移动文件(调工具)→ 汇报结果
```

**要求:全程不用人插手,机器人自己决定调什么工具、调几次。** 这段录屏 = 面试展示物。

### 3.3 危险场景(证明 guard 有用,面试讲点)

给机器人一个"删除文件"的危险工具,让它执行删除——系统必须拦下,要求人同意(或直接拒绝)。**录屏里演示一次"AI 想干危险事被拦住"**,比讲十句话都有说服力。

## 4. 功能需求

### 4.1 Agent 循环

| # | 需求 | 验收标准 |
|---|------|---------|
| F1 | 把用户输入 + 历史上下文发给 LLM | AI 能正常回复 |
| F2 | AI 要求调工具时,执行工具并反馈结果 | 循环继续,AI 基于结果再回答 |
| F3 | AI 直接回答时,返回给用户并结束 | 循环终止,不空转 |
| F4 | 设最大轮数上限(如 10 轮) | AI 死循环时自动停,不无限烧钱 |

### 4.2 工具系统

| # | 需求 | 验收标准 |
|---|------|---------|
| F5 | 工具注册:声明名字、参数(pydantic)、执行函数 | 注册后 AI 能调用 |
| F6 | 参数校验:AI 给的参数类型/必填检查 | 参数错 → 拦下报错,不执行真实函数 |
| F7 | 危险标记:工具可标记"危险" | 危险工具被调 → guard 拦截 |
| F8 | 未知工具:AI 调了没注册的工具 | 清晰报错"没有这个工具",不崩 |
| F9 | 结果检查:工具返回内容过长时截断 | 不把整个文件内容塞进对话 |

### 4.3 会话日志

| # | 需求 | 验收标准 |
|---|------|---------|
| F10 | 每步事件追加写入 JSONL 文件 | 任务跑完,文件里能从头看到尾 |
| F11 | 只追加,不修改不删除 | 程序没有"改历史"的代码路径 |
| F12 | 重启后恢复:读文件重建上下文 | 关掉重开,AI 记得之前聊过啥 |
| F13 | AI 的上下文从日志重建 | 日志是唯一真相源,没有第二份"内存版历史" |

### 4.4 演示

| # | 需求 | 验收标准 |
|---|------|---------|
| F14 | 命令行交互:启动后能对话 | 输入问题 → 得到回答 |
| F15 | 场景二录屏:真实任务无人值守完成 | 一段 2-5 分钟录屏 |
| F16 | 危险拦截演示 | 录屏里 AI 试图调危险工具被拦 |

## 5. 非功能需求

| # | 需求 | 说明 |
|---|------|------|
| N1 | 纯 Python 3.11,依赖最少 | 只用 openai 库(DeepSeek 兼容格式)+ pydantic + pytest,不引入框架 |
| N2 | 总代码量 ≤ 600 行 | 多了说明砍得不够狠 |
| N3 | 每步可运行可验证 | 不允许"写完全部才跑" |
| N4 | 测试覆盖核心规矩 | 至少 8 条不变量测试(见架构设计第 8 章) |
| N5 | 全程中文注释和文档 | 面试要能讲,中文讲最顺 |
| N6 | API 费用可控 | 演示用 DeepSeek,单次任务 token 成本 < 1 元 |

## 6. 验收标准(做完 = 以下全过)

- [ ] F1-F4:循环跑通"查天气给建议"(第 1-3 步完成)
- [ ] F5-F9:工具系统三关(拦截/校验/检查)有测试证明
- [ ] F10-F13:日志落盘、回放、重启恢复,有测试证明
- [ ] F14:命令行能对话
- [ ] F15:场景二(整理文件夹)录屏,无人值守完成
- [ ] F16:危险拦截演示录屏
- [ ] 8 条不变量测试全绿
- [ ] 代码 ≤ 600 行,注释中文,本人逐行能讲

## 7. 成功标准(这个项目到底成没成)

**成**:面试官问"你懂 Agent 吗",你打开录屏给他看"这是我写的框架,AI 想删文件被我拦住了,每一步都有日志能回放",他追问三个问题你都能接住(为什么只追加/为什么 guard 不能放行/为什么参数要校验)。

**不成**:代码写完但你自己讲不清为什么这么设计——那说明是抄的,不是懂的。

## 8. 风险与对策

| 风险 | 对策 |
|------|------|
| DeepSeek 工具调用格式不熟,卡在第 1 步 | 先打印一次原始返回,看懂结构再写循环(半天预留) |
| AI 循环烧钱(死循环一直调) | 最大轮数上限 + 单次任务预算检查 |
| 写着写着想加功能(插件?子 Agent?) | 回到 2.2 砍掉清单:不做的坚决不做,做完核心再说 |
| 时间拖太长失去动力 | 每步半天,4 步 = 2 天出活;先跑通再完美 |
