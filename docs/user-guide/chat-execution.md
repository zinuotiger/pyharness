# 在聊天窗口使用助手、执行环境和审批

输入框上方有两个入口：**助手**与**权限**。模型显示在它们下方。

- 助手是一套已发布的职责、工具与模型配置；发布版本不能原地修改。
- 执行位置决定代码在哪里运行：只聊天、本机、Docker、远程沙盒。
- 审批方式决定谁确认工具操作：人工，或独立后端规则审核器。
- “环境就绪”检查引擎和镜像等前置条件，实际创建容器仍可能失败。

## 日常操作

1. 点击“助手”，选择一个已发布助手，或者点击“添加自定义助手”。
2. 填写名称、职责、模型、执行位置、工具权限与审批方式，点击“创建并使用”。保存与发布是同一事务；重复请求有幂等凭据，相同配置优先复用已有版本。
3. 本机执行必须勾选明确授权提示。本机没有操作系统级隔离；团队账户继续禁用本机执行。Docker 不可用时不会改用本机。
4. 点击“附件”上传任务输入。附件归属于当前会话。
5. 发送任务。需要确认的调用会在聊天中显示审批卡片，包括实际代码、命令或文件参数。点击“批准本次”或“拒绝”。审批中心仍然可用。
6. 在“实际工具执行结果”和“本会话执行产物”查看结果。生成文件先预览，申请导出并在聊天中批准后下载；文件与 Patch 不会自动覆盖原工作区。

已有执行记录的会话绑定助手版本。更改助手、模型或执行位置时，点击“新建会话并切换”：原会话保留，草稿文字复制，附件重新存入新会话，避免复用其他会话的附件 ID。进行中的上传需先完成。草稿保存于当前浏览器的 sessionStorage，刷新可恢复；关闭浏览器会话、清除站点数据后不保证保留。

## 自动审核的范围

必须由用户在表单中选择“自动审核”。当前实现为独立的后端确定性规则审核器 `bounded-policy-v1`，不是另一个付费模型，也不等同于 Codex 的产品审核器。

- 仅处理 Docker / 远程隔离环境中，助手本来就有权限使用的操作。
- 当前任务明确要求写入对应相对路径时，可以批准小文件覆盖写入；明确要求打印或计算时，可以批准仅打印常量或简单算术的 Python。上下文缺失、用途不明确或有网络权限时转人工。
- 可拒绝明显越界的文件路径；原有路径守卫也会更早拒绝越界操作。
- 复杂 Python、Shell、本机操作、追加写入、Patch 应用、导出、网络及其他未列入白名单的操作仍需人工确认。
- 审核故障、超时、无效结果转人工。审核记录包括审核者、决定、理由、调用 ID、参数与上下文哈希、执行范围。
- 主助手无法调用审批接口或冒充审核者。批准仍经过原来的持久化裁决、队列恢复与执行前权限重查。

## 运行当前网页

在项目目录运行。使用新的独立数据目录查看新版界面；旧服务需要重启才能加载新的 Python API，单纯刷新页面不够。不要同时让两个进程写同一数据目录。

```powershell
Set-Location D:\zinuotiger-workspace\feature-worktrees\pyharness-platform-web-v1
python -B -m pyharness.web --data-dir D:\zinuotiger-workspace\temporary-runtimes\pyharness-chat-new\data --port 62041 --open-browser
```

新数据目录没有真实模型密钥，需要在设置中添加模型。若继续使用已有数据，请先正常停止其旧服务，再使用原来的 `--data-dir` 启动。不要复制、展示或提交密钥文件。

本次开发的浏览器验收地址是 `http://127.0.0.1:62040/`，使用测试模型、独立测试数据及真实 Docker；该测试模型固定生成测试任务，不代表真实模型回答质量。

远程服务的部署和认证说明见 [remote-sandbox.md](../remote-sandbox.md)。
