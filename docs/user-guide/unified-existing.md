# 已有成果统一候选使用说明

本候选把已存在的 Codex 执行器、飞书与个人微信适配、模块拆分、新版轨迹，与项目元数据、来源授权、Git/非 Git 快照、上下文清单、私有输入准备和本地管理员登录放入同一版本。来源主分支为 1e7bbb2，项目控制增量来自 7b1bdea 上的未提交工作区。

本轮范围仅为总计划第1–3步。项目输入准备仍不授予执行或宿主写回权限；文档阅读与引用、完整长任务恢复、DAG、交付独立验收及实验室等后续26项需求没有因此全部完成。原生壳保留既有功能，新增项目控制页面仍为Web入口，不声称新增功能双壳完全对齐。

## 使用独立数据目录启动

安装本候选 wheel 的 web extra 或从当前源码安装 `.[web]` 后，用 `pyharness-web --data-dir <新数据目录> --port 0 --open-browser` 启动。使用新的数据目录进行首次验收，禁止两个服务写同一目录。不要覆盖或清理原服务数据、已有模型凭据与未提交工作树。

需要普通密码登录时，先运行 `pyharness-web --data-dir <同一数据目录> --create-admin <管理员名>`，在终端交互输入并确认密码，再启动Web并通过 `/login` 登录。此本地管理员创建入口只在本机CLI提供，普通HTTP用户不能自报operator角色。

桌面WebView入口是 `pyharness-desktop`，可选Qt原生入口是 `pyharness-native`；它们需要对应desktop/native依赖。CLI为 `pyharness`，ACP沿原入口保留。

## 页面验收路径

- 左侧项目空间：创建/修订/归档项目，明确授权来源，查看并确认Git或非Git输入、持久快照和上下文清单，再准备私有输入。确认结果与执行权限分开。
- 设置中的飞书与个人微信：查看实际配置和绑定状态；本候选不复制旧服务秘密、不自动启用真实收发。
- 工具与连接：添加模型或Codex执行器。模型、客户端、渠道、沙箱配置齐备之前不把可见入口当成真实任务联通。
- 会话、运行详情和工作流：共用一个轨迹组件和受权查询接口，保留工具审批及产物预览/下载。
- 账户与团队：本地管理员与团队owner/member/viewer保持原有权限；退出密码会话后不能靠旧启动Cookie重新获得管理员访问。

## 安全与恢复

仍以ApplicationService组合服务、SessionLog持久事实、严格资源DTO、CAS/幂等和当前角色复查为边界；SQLite账户/渠道去重各守既有职责。两个来源中的executor.event与workspace.resource_committed均保留，注册事件83类、强同步16类。host_approved没有操作系统级隔离，isolated不可回退宿主。

验收与分发目录由交付报告列出。原四个工作区和私有恢复包继续保留；恢复时在新目录读回快照及摘要，不把历史文件覆盖用户的当前目录。原数据升级前应单独备份并核对服务停止和目录所有权。
