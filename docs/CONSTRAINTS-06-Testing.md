> 类型: 硬约束 | 权威: PRD-Core.md 验收 + 各 DIS 模块 GWT
> 适用: 全部 6 阶段,测试是用户主场(6 年测试出身)

## 1. 测试分层
| # | 约束 | 说明 |
|---|------|------|
| TS-01 | 三层测试 | 单元(模块内)/集成(跨模块)/端到端(真实 LLM 演示场景);每层有独立目录 |
| TS-02 | 不变量测试优先 | 核心不变量(只追加/guard 单调/参数先验)先写测试再写实现(RED→GREEN) |
| TS-03 | GWT 格式 | 测试描述用 Given/When/Then;验收标准与 DIS 中 GWT 一一对应 |

## 2. 覆盖要求
| # | 约束 | 说明 |
|---|------|------|
| TS-04 | 每模块 ≥3 条 GWT | 含正常路径+异常路径+边界 |
| TS-05 | 危险操作副作用断言 | guard 拒绝类测试必须断言真实函数零执行(副作用=0) |
| TS-06 | 错误码测试 | 每个错误码至少 1 条测试验证触发 |
| TS-07 | 测试不依赖真实 API | LLM 调用用 mock;真实 API 只留 e2e 标记测试(手动跑) |

## 3. 质量门禁
| # | 约束 | 说明 |
|---|------|------|
| TS-08 | 每阶段门全绿才进下阶段 | pytest 全绿 + 不变量测试通过 = 阶段门 |
| TS-09 | 修复必带回归测试 | 修 bug 先写失败测试证明 bug,再修复,防复发 |
| TS-10 | 覆盖率基线 | 核心脊柱模块覆盖率 ≥80%(pytest-cov) |

## 4. 如果违反会发生什么
- 违反 TS-02(先写代码后补测试): 不变量没钉死 → 某次重构悄悄破坏"只追加",测试没抓住 → 生产出 bug 才暴露
- 违反 TS-05(不断言副作用): guard 测试只验证"返回拒绝"没验证"函数没跑" → guard 拦截了但 executor 仍执行(实现 bug) → 测试假绿,安全实际失效
- 违反 TS-07(依赖真实 API): CI/本地测试网络抖动全挂 → 测试不可靠 → 开发者开始跳过测试 → 回归防线崩溃

## 5. 验收

- [ ] 核心不变量测试清单(≥8 条,见架构设计.md §8)全部存在且通过
- [ ] 危险操作测试含副作用断言(mock 断言调用次数=0)
- [ ] 测试目录结构: tests/unit tests/integration tests/e2e

## 6. 深度场景:测试假绿
**根因**: 测试写了但断言太弱(只断言"没抛异常")或 mock 太假(永远返回成功)。
**连锁后果**: 全绿但全是假绿 → 重构无保护 → 核心不变量悄悄破坏 → 面试演示当场崩(最坏情况);更糟的是开发者对测试失去信任,开始"跳过测试直接提交"。
**正确做法**: 不变量测试断言具体行为(append 后文件 hash 不变/guard deny 后函数调用次数=0/降级后请求走了备用 base_url);mock 要模拟真实失败(5xx/超时/坏 JSON)。

## 7. 核心不变量测试清单(先写测试再写实现,RED→GREEN)

> **口径统一(2026-09-12)**:本表此前的 INV-03/04/05/06/07/08 语义与 `PRD-Core.md`
> 的权威 INV 表(`PRD-Core.md:838`,冲突以 PRD 为准)不一致——曾把"guard 无放行 /
> 参数非法 / 强同步不丢 / 降级生效 / 循环必终止"记在这些编号上,导致同一编号在两份
> 文档里指两件事(代码注释与测试 docstring 也跟着混用)。现已按 PRD 对齐为本表,后续
> 新增引用一律以此为准;"循环必终止"不是不变量编号,而是 F007 循环护栏(由
> `max_turns` 用例覆盖,见 `tests/unit/test_agent_loop.py`)。

| # | 不变量 | 测试断言 | 对应设计 |
|---|--------|---------|---------|
| INV-01 | 日志只追加 / 历史必由日志派生 | append 后文件 hash 不变;无 delete/update API;derive 结果 = 逐事件重放 | 事件溯源 |
| INV-02 | 无绕过 agent-loop 直调 llm | 全库 `llm.chat` 唯一合法调用方 = agent-loop | 单一入口 |
| INV-03 | rebuild 与缓存一致 | `rebuild_from_log` 后缓存与重建前逐事件一致(含增量/编辑重放/二次 rebuild 无重复) | 派生视图可整体丢弃重建 |
| INV-04 | 无 guard 事件即非法执行 | 全链 allow 恰一条 `guard.evaluated`;模块无 bypass/放行/执行类方法面 | guard 单调拒绝 |
| INV-05 | guard 拒绝 = 零副作用 | 被拒调用后真实函数调用次数 = 0(拒后有 `guard.rejected` 无 `tool.result`) | 先验后跑 |
| INV-06 | 执行 args = 日志 args | 构造 N 例畸形参数:真实函数零调用,且 args/raw_args 双份逐字段一致 | LLM 零信任 |
| INV-07 | 单进程 | 全库进程数 = 1(无 multiprocessing / 跨进程 RPC;subprocess 工具除外且受 guard) | 单进程架构 |
| INV-08 | 阶段 import 方向 | 阶段 N 不得 import 阶段 N+1 模块(核心脊柱无环) | 依赖单向 |
| INV-09 | 日志脱敏 | 含 key 的输出在日志中为掩码 | 凭据安全 |

> 说明:降级链"主模型 5xx/401 后请求走备用"由 `tests/unit/test_llm_fallback.py`
> 覆盖,但它是**功能验收**(F013/F028),不是 INV 编号——早期把它记作 INV-07 的做法
> 已废弃。

## 8. 测试目录与命名规范
```
tests/
├── unit/            # 单模块, 无跨模块依赖
│   ├── test_session_append_only.py
│   ├── test_guard_monotonic.py
│   └── test_llm_parse_tool_calls.py
├── integration/     # 跨模块(不调真实 LLM, mock)
│   ├── test_loop_with_tools.py
│   └── test_fallback_chain.py
├── e2e/             # 真实 LLM(手动/CI 标记)
│   └── test_demo_organize_files.py  # @pytest.mark.e2e
└── invariants/      # 不变量测试(先写, RED 起步)
    └── test_invariants.py
```
命名: test_<模块>_<行为>.py;GWT 描述进 docstring: "GIVEN 事件已追加 WHEN 尝试修改 THEN 抛错"。

## 10. 面试叙事联动
测试策略是差异化武器。讲法: "我是测试出身, 这个项目我先把 9 条不变量写成测试(只追加/guard 单调/零副作用), 再让实现去满足测试——RED 到 GREEN。核心模块覆盖率 80%+。" 多数候选没有这个意识。
