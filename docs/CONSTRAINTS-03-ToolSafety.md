# CONSTRAINTS-03 — 工具安全约束

> 类型: 硬约束 | 权威: PRD-Core.md §6 + SECURITY.md + DIS-CORE.md §7
> 适用: tools 模块全部实现,面试安全叙事核心

## 1. 执行管道
| # | 约束 | 说明 |
|---|------|------|
| T-01 | 四关强制 | 契约校验→guard 单调→Provider 执行→结果检查;禁止跳过任一关直达执行 |
| T-02 | guard 只拒绝不放行 | 单调拒绝语义;guard 返回三值: allow/deny/ask,但 deny 不可被后续覆盖 |
| T-03 | 参数校验先于执行 | pydantic 校验失败 → 不执行真实函数,返回结构化错误 |
| T-04 | 危险工具分级 | danger 分级表(见 SECURITY.md §4);高危工具默认审批 |

## 2. 工具注册
| # | 约束 | 说明 |
|---|------|------|
| T-05 | 工具定义完整 | name/description/参数 schema(pydantic)/执行函数/危险级别 五要素缺一不可 |
| T-06 | 同名注册拒绝 | 重复注册报错,禁止静默覆盖 |
| T-07 | description 防注入 | 工具描述不允许含"忽略之前指令"类文本;描述与执行同谓词 |

## 3. 结果处理
| # | 约束 | 说明 |
|---|------|------|
| T-08 | 结果校验 | Provider 返回值不符合声明 schema → 标记异常 |
| T-09 | 输出有界 | 超长结果截断或 spill(落盘给指针);禁止整文件内容进上下文 |
| T-10 | 敏感脱敏 | 工具输出含 key/token/密码 → 脱敏后才进日志与模型上下文 |

## 4. 如果违反会发生什么
- 违反 T-02(guard 可放行): AI 的 delete 调用被业务 guard 拒绝后,插件层"放行"→ 文件被删,安全体系成摆设
- 违反 T-03(不校验): 模型调用 `read_file(path=123)` 或注入路径 → 崩溃或越权读文件
- 违反 T-09(无界输出): 读 100MB 文件进上下文 → token 爆炸,单次调用超预算

## 5. 验收
- [ ] 危险工具(delete/覆盖写)在无审批时调用被拒,且真实函数零副作用(测试断言文件未变)
- [ ] 被 guard 拒绝的调用无法被任何后续环节放行(不变量测试)
- [ ] 非法参数(类型错/缺必填)返回结构化错误码(TLB-8xx)且函数未执行
- [ ] 超长输出触发截断/spill,上下文 token 有界

## 6. 深度场景推演:如果违反工具安全约束会怎样

### 场景 6.1:guard 被设计成"可以放行"(违反 T-02)
**根因**: 开发者觉得"guard 能拒绝也能允许更灵活",或为省事让一个 guard 同时管黑白名单。
**连锁后果**: ① 安全策略从"单调收紧"变成"可协商" → 恶意 prompt 诱导模型调用危险工具时,只要有一个 guard 返回"放行"就绕过所有拒绝;② 多个 guard 的语义变成"任一放行即放行",与"任一拒绝即拒绝"完全相反——这是**方向性错误**,审计时极难发现因为单测都过了;③ 面试被问"guard 为什么不能 allow",如果项目里真有 allow 语义,整个安全叙事崩塌。
**正确做法**: guard 只返回 allow/deny/ask,allow 只是"本 guard 不反对",最终执行权在管道:任何 deny 即终止(单调),ask 走审批,全部 allow 才执行。

### 场景 6.2:参数校验放执行后面(违反 T-03)
**根因**: "先跑起来看结果再说",或把校验当可选增强。
**连锁后果**: ① 模型传 `delete_file(path="C:\\Users\\*")` 或 `write_file(path="config.py", content="恶意代码")` → 真实函数已执行,校验在后 = 事后诸葛亮;② 危险操作在"校验"前已造成副作用,且日志可能没记(校验失败的调用没进日志?记了但为时已晚);③ 这正是"LLM 零信任"原则最核心的一条,违反它 = 安全模型整个失效。
**正确做法**: 校验是执行的前置闸门,校验失败 = 函数零调用(用 mock 断言函数未被调用)。

### 场景 6.3:工具输出不脱敏直接进上下文(违反 T-10)
**根因**: "本地自用,没有敏感数据"。
**连锁后果**: ① 读文件工具读到一个含 API key 的配置文件 → key 原文进模型上下文 → 模型可能把它写进总结/日志/回放文件;② 会话日志是纯文本 JSONL,key 永久留在磁盘;③ 将来项目开源(面试作品要开源),key 随日志泄露。
**正确做法**: 输出闸口做正则脱敏(密钥模式: sk-[a-zA-Z0-9]{20,} 等),日志与模型上下文都只见掩码。

## 7. 危险工具分级表(实现参照)
| 级别 | 定义 | 默认策略 | 示例 |
|------|------|---------|------|
| L0 安全 | 无副作用 | 直接执行 | get_weather/列目录/读文件(白名单内) |
| L1 低危 | 有副作用但可逆 | 执行+记日志 | 写临时文件/重命名 |
| L2 中危 | 副作用难逆 | 审批 ask | 移动文件/覆盖写 |
| L3 高危 | 破坏性 | 默认拒绝+审批 | 删除文件/删除目录/执行任意命令 |
| L4 禁区 | 系统级 | 硬拒绝不可审批 | 改权限/格式化/改系统配置 |

## 8. 工具安全验收 GWT(核心三条)
- Given 一个 L3 危险工具被调用, When 无审批通过, Then 调用被 guard 拒绝,真实函数零执行(副作用断言),事件日志记录拒绝原因
- Given 模型传非法参数(类型错误), When 进入执行管道, Then 校验拦截返回 TLB-8xx,函数未执行,错误喂回模型
- Given 工具返回超长输出(>100KB), When 结果检查, Then 截断或 spill 落盘,上下文仅含指针与摘要
