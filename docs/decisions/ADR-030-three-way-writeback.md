# ADR-030：固定三方合并与显式目标写回

状态：S11 已实施，整体验收中。先前阶段的完成报告不能作为本阶段通过证据。

总计划 S11/C03 授权增加受控合并与写回；仅替代“产品工作副本没有任何宿主写回入口”的历史排除范围。原 SourceGrant、GuardChain、工具审批、隔离执行与只读额外目录仍按原契约执行。团队账户的宿主执行禁令保持；团队实际工具效应验证使用隔离 Docker。

1. 基线来自原正式任务所固定 WorkspaceInput 的精确私有字节；结果来自 S10 固定交付包和当前有效的独立主体验收。当前目标通过新的具名写范围读取，不能冒充输入基线，也不能从模型文本推断宿主路径。
2. 真实 owner 明确签发 `writeback_grant`，固定项目、接收账号、根目录物理身份、具体相对路径、replace/create/delete 操作及 UTC 到期时间。原只读 SourceGrant 不具有写权限。每次使用复查真实主体、owner/recipient 当前成员资格、项目版本、来源、验收和目标根身份。
3. `merge_plan` 固定基线、当前目标、交付结果、合并字节、内置验证版本与批准摘要。原字节、BOM、CRLF 不归一化。相同版本直接采用；不重叠文本改动可合并；重叠、歧义、超限和不支持格式阻塞。删除须引用同一原执行中实际观察的最终删除收据，不能靠模型声称删除。
4. `writeback_application` 先强提交 admitted 意图，再执行指定文件操作，最后强提交 revision 2 的实际结果。意图未确认时零目标写入；同一方案只允许一次申请，换键或换 application ID 不能重放。冷读 admitted 派生 unknown，不能靠重启补执行。
5. Windows 使用实际独占文件 handle，并保持目标根与父目录 handle；先检查所有已有目标，再提交意图。创建使用 CREATE_NEW，删除作用于持有的准确 handle。不能取得此边界的系统仅支持预览和明确授权的结果导出，不回落不安全的宿主应用。
6. 多文件写回不宣称全局原子事务。逐文件读取并核验实际结果；完整、部分、失败、未知分别记录。不会自动回滚或盲目重试。强结果回执丢失仍沿原意图核对。内置验证器只做内容策略与 Python/JSON 语法解析，不执行用户代码或 shell。
7. 合并结果下载另行提交 `merge_export`；预览、保存方案或原交付导出授权均不自动授予合并结果下载。复查范围与当前来源后只返回指定冻结文件。

所有新事实仍由唯一 WorkspaceStore 的控制 SessionLog 强提交和私有摘要寻址文件承载，未增加数据库、模型、引擎或任务队列。历史验证只检查当时的结构、身份、版本与因果关系，不读取今天的目标文件来否定旧事实。当前授权另行检查。

NTFS 设备及文件编号可能超过 JavaScript 精确整数范围；新 MergePlan 的目标身份以十进制字符串保存和传输，保证浏览器、私有 blob 和批准摘要一致。原已验收的 SourceSnapshot 与 SourceGrant Schema 不变。S11 首轮开发期间含整数目标编号的合成测试记录仅作失败证据保留，不作为已发布数据版本或本阶段交付。
