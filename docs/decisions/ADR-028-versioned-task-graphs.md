# ADR-028 产品任务图与原受控执行链

状态：S09实施中，尚未验收。依据当前用户明确授权的总计划S09/C01增量。

## 元信息

日期：2026-10-19。落点：S09/C01。原则：ADR-001/002/003/005/006；保留原owner、事件溯源、能力分层、单进程调度和单调拒绝。适用新产品任务图，不变更已有顺序workflow数据或执行语义。

## 背景

ADR-017仍约束既有WorkflowRunner的顺序步骤与segment治理。本决策仅替代“新增产品任务图不实现DAG”的历史排除范围；不迁移、删除或改名旧顺序workflow，不以旧steps接口伪装图运行。后续恢复、交接、验收、写回和浏览器仍分别遵循相应阶段边界。

## 决策

图定义是原WorkspaceStore控制日志上的独立版本资源。每节点固定同项目/主体的ProductTask精确引用、文档/引文/交付版本及published Agent引用；不接受工具代码、任意条件表达式、宿主路径或客户端身份/权限。节点最多20个，ID唯一，依赖唯一、存在且非自身；稳定Kahn排序拒环。定义保存、读取与预检均不启动运行。旧图不随当前任务或Agent编辑自动改写。

显式图运行须另有原owner强确认的授权，绑定图引用、当前来源与执行环境、节点唯一准入身份、并发和预算分配。并发1–4；图额度包含输入/输出/工具数和整数微元，避免跨语言浮点规范化歧义；既有Agent的预算不因此扩大。应在原RunAttempt及ExecutionAuthorization上绑定图节点，防普通开始绕过图额度/取消；节点仍经原Queue、AgentLoop、Scope、Guard和Approval，不另建任务权威库。

## 后果与运行边界

图授权与不可变调度意图统一保存在原控制日志，由同一OS单写者强确认；实际结果仍在原节点运行日志，避免增加第二份Root运行权威。确认意图后才准入节点。重启只读观察，不凭无本地queue判断未执行，不把中断/未知节点当已完成，不自动重发旧动作。原键与固定节点身份用于核对未知提交，旧授权Root不再投递。当前图节点的通用S08续做入口明确拒绝并在只读预检列出graph_continuation_requires_scheduler_admission；不会把新attempt当成解除图归属或取消的通道。普通schema1/2执行继续保留原S08续做功能。图自身重启不自动续调，未执行节点显示中断；显式图恢复调度属于后续独立准入扩展。

菱形D依赖B/C全部确认技术完成且没有未知效果/产物。技术完成不是S10独立业务验收，依赖边不隐式复制或重新归属上游产物；交接与写回在S10/S11完成。图取消冻结新准入并传播到实际已授权节点及合法续做后代；撤回资料读取权限后仍保留同creator/tenant的最小停止通道，不读取正文或扩大权限。

## 违反后的具体失败

把顺序step列表当DAG会使D在B或C尚未完成时提前启动；把“冷服务没有queue”当作节点未执行会在强退重启后重复实际写入。若节点attempt缺少图绑定，普通Start或续做入口会绕过图取消与并发/预算分配。若用最新任务替换旧图中的固定引用，用户看到的图版本与实际输入将不一致。

## 备选方案

继续使用顺序WorkflowRunner保留原功能，但不满足菱形依赖；另建任务数据库和新执行器会复制授权、治理与恢复机制。选择原控制日志上的独立图协议、原控制日志强意图和原执行器准入，承担显式版本与跨日志核对成本，不以持久缓存充当第二权威。
