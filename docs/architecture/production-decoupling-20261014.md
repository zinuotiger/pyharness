## 执行批次

1. **HTTP 与桌面入口**：DesktopApp 保留兼容方法，身份与令牌、页面及资源、路由注册、会话与交互、管理用例、关闭生命周期分别归属专门模块。platform_api 保留挂载入口，渠道、任务、知识、产物和连接按功能成组注册。原生窗口按视图构建、会话交互、管理操作分组。
2. **应用服务**：ApplicationService 保留会话运行装配与所有公开方法；模型及租户设置、会话历史投影、审批与反问、编排、插件技能与工作流分组。PlatformService 保留组合入口，助手版本、任务调度、产物、知识与连接各自负责。
3. **CLI 与引擎**：命令解析、渲染、会话启动、交互循环、查询命令、编排命令、离线维护分别迁移。引擎拆出类型、策略编译、工具装配、任务执行及证据归档，入口保留生命周期协调。
4. **核心能力**：模型适配拆成协议类型、流协议、用量、传输与客户端；工具守卫拆成规则、路径检查、链和配置；工具执行、审批、子任务、调度器按完整生命周期职责分组。持久化拆出锁、读取、追加写、修复与轮转；索引查询拆出投影与维护；配置模型、事件载荷、作用域模型和其他边界能力分别迁移。
5. **回归及结构验收**：全量生产行数扫描；入口/核心/适配器依赖图，区分运行时导入、延迟导入和类型引用；检查新增循环；对比公共符号、命令及 HTTP 路由；运行现有测试；检查 Web、桌面和原生加载；核对测试/脚本指纹。

## 迁移规则

兼容 facade 只重导出和协调，不复制实现。类内职责通过专门协作类组织，保留公开对象身份、签名、装饰器和调用行为。底层职责模块不得反向依赖组合 facade；明确依赖方向，不引入巨型 shared/common 模块。以现有测试与接口清单验证行为；已有延迟循环单独记录，不把类型引用误报为运行时循环。
