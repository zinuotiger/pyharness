# 受控浏览器工作台（S17，尚未整体验收）

> 当前状态更新（2026-10-21）：本规格对应能力已在S08–S18相应阶段及S18统一版本中验收。下文旧阶段状态为实现历史，当前边界与交付核验见[统一版本说明](unified-delivery.md)。S19最终交付须以新源码冻结和新CI为准。


当前支持 Windows、本地 operator、独立临时 Chrome。需安装受信任的 Node、Playwright Node 模块、Chrome/Chromium，工作台不自动下载安装或运行任意命令。

1. 工具与连接 → 受控浏览器，输入三个绝对路径与允许源。Playwright 填模块的 index.js 文件，不填目录；源只含协议、主机与端口，不含用户名、口令、路径、查询或片段。
2. 检查生成只验证本地配置，零进程、不保存。选择“带入原连接保存表单”，检查后保存，初始禁用。保留生成的真实解释器与隔离启动参数，避免 Windows venv 重定向器被结束后留下实际服务。
3. 原连接页启用。可先使用原 MCP 调试发现四个工具；发现只加载协议，不打开 Chrome，不代表这些动作已获审批。
4. 发布助手：standard、host_approved、绑定连接，明确列出 mcp.连接名.open、observe、act、close 中需要的权限。团队账户仍禁止宿主执行。配置变更须按原流程重新预检任务，不修改在途任务。
5. 在项目任务收件箱选择固定助手版本，预检并提交。工具请求先经过原工具权限和高危险审批；本地浏览器的 DOM 操作同样不会绕过审批。页面文字是不可信输入。
6. open 参数为允许源下的 url；observe 返回一页最多4个顶层目标。act 的 session/generation/target/label 必须来自最近一次观察，action 为 click，或 fill 加 text。密码、上传、任意脚本、物理输入均不开放。DOM/导航变化、上一次动作或重新观察会使旧引用失效；先重新观察再请求新的批准。
7. 原任务观察与工具消息读取实际返回结果及效果收据。拒批不会调用浏览器动作；批准只证明原链放行，标签与 DOM 动作成功不证明外部业务最终验收。
8. 使用 close 关闭载体，或关闭该任务会话。超时、取消或协议失败会永久废弃此载体，不会自动重启或重发动作。未确认动作的外部效果可能已发生，先核对目标系统。Windows Job清理自有子树，不清理其他浏览器和用户进程。强杀或外部程序占用可能留下临时文件，不能把进程退出宣称为文件已全删除。

精确源过滤及禁止弹窗/下载/服务工作线程是浏览器操作限制，不是 OS 网络隔离，也不抵御被替换的本地二进制。此版本不接入个人浏览器登录态；不评价付费模型或外部网站实际业务质量。
