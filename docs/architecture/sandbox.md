# Sandbox architecture

SandboxManager owns one private workspace per run and a backend selected by the immutable Agent version. Modes are disabled, host_approved and isolated. Disabled refuses execution and high-risk writes with sandbox_disabled. HostApproved uses the existing ProcessOwner to bound time/output and reap process trees; it provides no OS boundary. Docker failure returns sandbox_unavailable with no host fallback.

Private copy excludes dot files, Git metadata, credential filenames, dependency directories and links, and limits file count/bytes. Empty creates a fresh workspace. private_git_clone supports bounded local repositories with a plain .git directory: a no-hardlink bare clone under sanitized Git configuration, then a verified ordinary-file archive; it does not fetch a remote URL, run checkout filters or preserve .git in the final workspace. Git worktree indirection and oversized repositories are explicitly rejected.

Docker runs a locally installed image with pull=never, network=none, non-root UID, all capabilities dropped, no-new-privileges, read-only root, bounded writable tmpfs, CPU/memory/PID limits and only the private workspace mounted. No Docker socket, user HOME, Git credentials or host environment secrets are passed. Docker client configuration uses a private directory. An operator-managed Docker daemon and preinstalled image are required.

exec.shell_run, exec.python_run and proc.start/status/kill route through the same governed backend. fs.read_file/list_dir/write_file/patch and file.read/list/write/patch use the private path broker. Path traversal, Windows device names, symlinks and junctions are rejected. proc.kill in Docker destroys the run-owned container, not just a numeric PID. PTY is intentionally unsupported. Command results produce a bounded test-report.json; text file differences produce a patch plus an integrity-checked manifest. Application to the input workspace and export require separate human approvals.

Destroy retries are bounded. Cleanup failures retain diagnostic ownership for retry; after process restart historical live records display orphaned, never healthy. The UI can reclaim a recorded orphaned container after verifying its managed and tenant-owner labels; unrelated containers are never adopted. Container file operations use a bounded stdin broker. Host snapshots pause the container before any file reads and thaw it afterwards. Nonblocking descriptor reads reject FIFOs/devices.
