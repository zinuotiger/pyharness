## Context

### 现象（R31-1 后仍存）

`X-PyHarness-Tenant` 头是**未认证的声明**：全局单 `_api_token` 能开所有租户。最小攻击链不需要任何漏洞——

1. 取得全局令牌；
2. `GET /api/tenant` → 响应内含 `"tenants": [...]`，**枚举全部租户名**（`tenant_settings.list_tenants()`）；
3. 带 `X-PyHarness-Tenant: <目标租户>` 访问任意会话/设置。R31-1 会**放行**，因为声明与权威归属一致。

### 三个概念必须分开

| 概念 | 变更前 |
|---|---|
| tenant **ownership** | 已闭合（R31-1） |
| tenant **authentication** | 不存在（只有全局单令牌，无租户凭证） |
| tenant **authorization** | **不存在**（无「该主体可用哪些租户」的规则） |

### 与既有文档的冲突（本 ADR 的契约变更依据）

- `docs/CFG.md` §9 原文：「该隔离是应用级逻辑租户，**不是**针对同一 Windows 用户的强安全边界」。
- `docs/SECURITY.md`：「单进程无网络层身份伪造」——该判断在 HTTP 面存在后**已过期**。

本 ADR **升级**上述口径：租户从「逻辑分区」升级为「**经凭证绑定的访问边界**」，并如实声明该边界**止于何处**。

### 威胁模型（诚实边界）

服务仅绑 `127.0.0.1`；数据在**同一 Windows 用户**的 `~/.pyharness/` 下。因此：

- 同用户且**能读文件**的进程：**本来就能直接读** JSONL 与令牌文件 ⇒ 本机制**不防**它。
- 本机制真正挡住的是：**能连上回环端口、但读不到该用户文件**的进程（沙箱应用、受限服务账户），
  以及**将来端口被暴露时**的外部客户端。
- 桌面 UI 自身由壳注入凭证，因此**用户仍可自由切换自己机器上的全部租户**——这是产品语义（同一用户拥有全部租户），不是缺口。

## Decision

采用**方案 B 的最小形态**，四条不变式：

1. **凭证绑定租户**：每个非 `default` 租户在自己的租户目录下有 `token` 文件（32 字节 hex，原子写 + `chmod 0600`——**后者仅 POSIX 生效**，Windows 见 Consequences「0600 在 Windows 上不成立」）。
   声明该租户的请求**必须出示**该令牌（`X-PyHarness-Tenant-Token` / 同名 cookie / `?token=`），否则 **401**。
   **创建路径 = 引导页**：持**操作者令牌** + `?tenant=<t>` ⇒ 铸/取该租户令牌并下发其 cookie。
   （缺此条则该租户既无令牌可出示、又无生成路径 ⇒ **永远 401**；见 Consequences「已修」。）
   这**不放宽**边界：操作者令牌本就等同「同用户文件访问」这一既成信任级。
2. **鉴权先于归属**：中间件先鉴权（401）再做归属判定（403）。故未授权方**无法**通过 403/404 之差探测
   「某租户下是否存在某会话」。
3. **`default` 是兼容口**：沿用全局 `shell.web.token`，不需要租户令牌。否则桌面壳与全部既有客户端即刻断。
4. **校验只读，不得凭空铸令牌**：`verify_token()` **只读**；令牌只由壳/运维显式生成。
   （若校验路径可生成，任何人报一个租户名即可得到自己的令牌副本 ⇒ 授权空转。）
   配套：引导页 `/` **不再无条件发放**全局令牌，必须出示凭证——它曾是「任何本机进程 GET / 即得令牌」
   的免费发放点，有了租户令牌后，拿到全局令牌即可换任意租户 cookie。

### 凭证模型（两层，缺一不可）

| 层 | 位置 | 作用 |
|---|---|---|
| 租户**授权** | 中间件，**先跑** | 声明非 `default` 即须出示该租户令牌，否则 401。**这一层才是安全边界。** |
| API **鉴权** | 各路由的 `_require_api_auth` | 接受**操作者令牌** *或*（非 default 时）**本租户令牌** |

第二层若只认全局令牌，则"只拿到租户 cookie"的浏览器会**进得了页面、调不动接口**（探针实测 401）。
故第二层必须认得租户令牌；这不会放宽边界 —— 第一层已经在路由之前把非 default 的租户授权卡死了。

### 凭证投递

| 场景 | 投递方式 |
|---|---|
| 桌面壳（pywebview） | `DesktopApp.bootstrap_url()` 把操作者令牌放进加载 URL；随后换成 HttpOnly cookie |
| 浏览器（`shell.web.token` **未配置**） | 壳启动时把**进程随机**的操作者令牌落盘到 `<storage.root>/web.token`（权限见 Consequences，只记路径不记值），访问 `/?token=<该文件内容>` |
| 浏览器（`shell.web.token` **已配置**） | 直接用配置值；**不落盘**（用户已知该值，无需多一份副本） |
| 浏览器访问非 default 租户 | `GET /?tenant=<t>&token=<该租户令牌>` → 服务端校验后下发同名 HttpOnly cookie；前端零改动 |
| 外部 API 客户端 | 读 `~/.pyharness/tenants/<t>/token`，带 `X-PyHarness-Tenant-Token` |

> **为什么必须落盘**：`/` 收紧为"须出示凭证"后，若令牌是随机且不打印，浏览器用户**无从取得** ⇒
> 该入口等于被关闭（实测改动后浏览器 401 且无处可查）。落盘是与租户令牌同口径的最小补救；
> 不写日志、不进 API 响应，只记录**路径**。

## Consequences

**正**
- 非 `default` 租户从「报对名字即可进」变为「必须持凭证」；跨租户声明被 401（而非仅 403）。
- 引导页不再是令牌免费发放点。
- `tenants_dir()` 收口了租户根目录的派生（此前读写两侧各写一遍）。

**负 / 已知代价**
- **破坏性**：既有只持全局令牌就去访问非 `default` 租户的客户端会得到 401，必须改带租户令牌。
- 浏览器使用非 `default` 租户需一次性提供 `?tenant=&token=`。
- 令牌文件是**明文**（与同目录下的 JSONL 同级）；不落日志、不进 API 响应。
- **不防**同用户且能读文件的进程（见上）。
- **「0600」在 Windows 上不成立（2026-09-21 UI 验收实测更正）**：`chmod` 在 NTFS 上无效，
  `stat.S_IMODE` 实测为 `0o666`。实际可读面由**父目录 ACL 继承**决定 —— 默认
  `%USERPROFILE%` 下只含当前用户 + SYSTEM + Administrators（等效「仅属主」）；
  但若该目录被外部工具**额外授权**（本机实测存在一条 `本机额外 ACL 授权组（具体机器信息未分发）:(OI)(CI)(RX)`），
  令牌文件会继承该授权。**故 Windows 上不得声称「0600」**；要收紧须显式改 ACL（**未做**）。

**已修（2026-09-21，UI 验收发现）**
- **租户令牌在生产路径不可达**：`TenantSettingsStore.api_token()` 初版在别处**零调用点**，
  应用永不创建 `tenants/<t>/token` ⇒ 非 default 租户永远 401。已在引导页补上创建路径（见 Decision 1）。
- 中间件原先把 `?tenant=<t>` 的引导页请求也当作普通请求拦截 ⇒ 创建路径**根本到不了**；
  现引导页由自身把关（它比中间件多一条「操作者可铸令牌」规则）。

**未做（显式）**
- 不改 `Principal` 的通道契约（不加租户维度）—— 那会触发 N5 五态契约变更，本 ADR 不含该授权。
- 不引入新进程/端口（H-04）。
- 不做令牌轮换/吊销流程（最小形态；需要时另开）。

## Alternatives

| 方案 | 未选原因 |
|---|---|
| **A** 每会话能力令牌 | 把授权降到**会话**级：仍可在任意租户**新建**会话 ⇒ **不闭合** L-1 的鉴权面 |
| **C′** 不加锁，只收紧 + 文档声明 | 零破坏，但等于**承认不做**鉴权；与 owner 的目标（真正闭合）不符 |
| **D** 只锁写操作 | 读仍可跨租户 ⇒ 部分闭合，留口子 |
