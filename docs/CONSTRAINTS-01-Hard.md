## 4. 如果违反会发生什么
- 违反 H-05(存第二份历史): 日志与内存不一致 → 回放结果与现场不符 → 调试灾难,审计失效
- 违反 H-07(引入 allow): 一个插件放行被拒调用 → 权限策略被绕过 → 危险工具可被任意调用
- 违反 H-08(引入 LangGraph): 学习价值归零,面试叙事从"我造的"退回"我用的"

## 6. 深度场景推演:如果违反硬约束会怎样

### 场景 6.1:有人在第 3 阶段偷偷引入 SQLite 存会话日志(违反 H-09)
**根因**: 开发者觉得"JSONL 太原始",想用数据库的查询能力顺手存日志。
**连锁后果**: ① 会话日志进了数据库 → 事件不再是人类可读的纯文本,回放要写 SQL;② JSONL 的 append-only 语义在数据库里变成可 update/delete → 某天有人写了 UPDATE 修"历史错误",审计链断裂;③ 崩溃恢复逻辑要重写(数据库事务 vs 文件原子写是两套);④ 面试时被问"你的日志为什么不用数据库",回答变成"我当初图省事"。
**正确做法**: 日志永远 JSONL(真源),查询需求第 5 阶段用 SQLite FTS 建**索引副本**——索引可以重建,真源只有一份。

### 场景 6.2:第 4 阶段想并行加速,把子 Agent 拆成独立进程(违反 H-04)
**根因**: asyncio 并发不够"过瘾",想上 multiprocessing 真并行。
**连锁后果**: ① 子进程无法共享内存事件总线 → 要引入 IPC/消息队列,复杂度翻倍;② 会话日志多进程写同一文件 → 原子写失效,需要文件锁;③ 崩溃时子进程状态丢失,主进程不知道;④ 单进程架构的"一切可回放"承诺被打破——部分事件在别的进程内存里。
**正确做法**: 单进程 asyncio 并发足够(IO 密集的 LLM 调用不吃 CPU),真并行留到确有瓶颈时再议。
