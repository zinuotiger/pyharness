# Mini-Harness 架构设计文档 v0.1(精简版)

> 用途:动手写代码前的图纸。只讲架构,不引用 DSH 源码。
> 读者:许子诺(会 Python,懂 Agent 概念,不需要 TS 细节)
> 原则:先跑通,再严谨。每一章都能独立看懂。

---

## 1. 一句话定位

**Mini-Harness 是一个"会自己干活的小机器人框架":你给它一个任务,它自己决定先干什么后干什么,每一步都记在本子上,随时能翻。**

它是 DeepSeek Harness 的"思想复刻",不是"源码复刻"——只拿走 DSH 最核心的 3 个架构设计,其余 90%(插件树、compaction、subagent、web UI…)全部砍掉。

## 2. 要什么 / 不要什么

| 要(核心 3 件) | 不要(砍掉的外围) |
|---|---|
| Agent 循环(大脑) | 插件系统(Cordis) |
| 工具系统(手) | 上下文压缩 compaction |
| 会话日志(本子) | 子 Agent |
| 危险操作拦截 guard | Web UI / ACP / Python SDK |
|  | 250 个 npm 包的依赖管理 |

**为什么砍**:你的目标不是再造 DSH,是**亲手理解 Agent 框架的骨架**。骨架 = 大脑 + 手 + 本子。其他都是长在骨架上的肉。

## 3. 整体架构图

```
用户输入
   │
   ▼
┌───────────────────────┐
│   Agent Loop(大脑)     │  循环:
│   1. 把上下文发给 LLM  │  调 LLM → AI 说要调工具?
│   2. AI 回答 or 要调工具│   ├─ 说人话 → 返回给用户,结束
│   3. 循环直到 AI 说完   │   └─ 要调工具 → 交给工具系统
└─────────┬─────────────┘        → 结果喂回 → 再调 LLM
          │ 每一步都追加记录
          ▼
┌───────────────────────┐
│   Session Log(本子)    │  append-only 事件日志(JSONL 文件)
│   · 用户说了啥         │  唯一真相源:AI 看到的上下文从这里重建
│   · AI 说了啥          │  · 可回放:任务过程从头看到尾
│   · 调了哪个工具+结果  │  · 可恢复:关掉重开还记得
└───────────────────────┘

          ▲ 工具调用请求
┌───────────────────────┐
│   Tool System(手)      │
│   guard  →  执行  → 检查│
│   (危险拦截) (参数校验后跑) (结果合规?)
└───────────────────────┘
```

**数据流一句话**:用户输入 → 大脑决定(调 LLM)→ 如果要工具就伸手(工具系统)→ 每步都记本子(会话日志)→ 结果再回到大脑 → 直到任务完成。

## 4. 三个模块,各干什么

### 4.1 Agent Loop(大脑)— 最核心,约 100 行

**职责**:驱动循环。一句话:**"调 LLM,看它说什么,直到它说完了。"**

```
运行中状态:
  while True:
    1. 从本子取上下文(所有历史)
    2. 发给 LLM
    3. AI 回答里没有工具调用 → 返回给用户,循环结束
    4. 有工具调用 → 交给工具系统执行 → 结果写回本子 → 回到 1
```

**关键概念:LLM 每次只做两件事之一——说人话,或要求调工具。** 循环的意义:一次调 LLM 不够,AI 可能要先查资料(调工具)才能回答,所以要反复调,直到它认为信息够了。

**DSH 给的思想**(不是源码):循环是有状态的——空闲(idle,没在干活)、运行中(running,正在干活)。一个 agent 同一时间只跑一个任务。

### 4.2 Tool System(手)— 约 100 行

**职责**:让 AI 能"动手"。AI 说"我要调 get_weather(city=广州)",系统负责:这工具存在吗?参数对吗?危险吗?执行!结果对不对?

```
工具定义(每个工具三样东西):
  名字:  "get_weather"
  参数:  {city: 字符串,必填}        ← 用 pydantic 声明
  干什么: 查天气(你写的真实函数)

调用管道(三步):
  ① guard(危险拦截):这工具有没有标记"危险"?危险要人同意
  ② 执行:参数校验(用 pydantic)→ 跑真实函数
  ③ 检查:返回结果符合声明吗?超长就截断
```

**两条铁律(面试能讲深的关键)**:

1. **LLM 是不可信组件**——它给的参数可能是错的(类型不对、缺字段),甚至可能试图调危险工具。所以参数必须校验,不能直接信。
2. **guard 只能拒绝,不能放行**——任何一层检查都可以说"不行",但没有谁能说"我放行了,不用管别人"。安全只能越收越紧,不能越放越松。

### 4.3 Session Log(本子)— 约 80 行

**职责**:记下每一步,只追加、不修改、不删除。这是 Mini-Harness 跟"随便写的循环"的分水岭。

```
事件类型(三种,够用):
  user/message     用户说了什么
  assistant/message AI 说了什么
  tool/result      调了哪个工具、结果是什么

存储:JSONL 文件(一行一个事件,append 追加)
  第 1 行:  {"type":"user/message",      "content":"帮我查广州天气"}
  第 2 行:  {"type":"assistant/message", "content":"", "tool_call":"get_weather(city=广州)"}
  第 3 行:  {"type":"tool/result",       "content":"25度,晴"}

回放:把文件从头读一遍 = 任务全过程
恢复:重开程序时读这个文件 = AI 还记得之前干了啥
```

**三条铁律**:

1. **只能追加**——历史是事实,改历史 = 造假。要改只能"追加一条修正",不能抹掉旧的。
2. **AI 看到的上下文从日志重建,不单独存**——本子是唯一真相源。想查"AI 当时到底看到了什么"?从头把日志读一遍就是。
3. **日志要先校验再写入**——写进去之前检查格式对不对,坏数据不让进本子。

**为什么这个设计值钱(面试话术)**:别人出 bug 查日志,你说"我的每一步都是事件,能完整回放,还能从日志重建 AI 当时看到的所有内容"。

## 5. 关键技术决策(为什么这么设计)

| 决策 | 为什么 | DSH 同款思想 |
|---|---|---|
| 消息历史从日志派生,不单独存 | 单一真相源:不会出现"日志说 A,内存说 B" | 事件溯源(Event Sourcing) |
| 日志只追加 | 历史不可变,出错能回放定位 | append-only log |
| guard 只拒绝不放行 | 安全策略只能收紧,防止被钻空子 | guard 单调性 |
| 参数用 pydantic 校验 | LLM 输出不可信,先验后跑 | runtime arg validation |
| 工具结果要检查 | AI 会把垃圾结果当真 | 输出校验 |
| 循环有 idle/running 状态 | 防止一个任务没跑完又开一个 | 三态机 |
| 每步都记日志 | 可回放 = 可调试 = 可审计 | 事件日志 |

## 6. 文件结构(全 Python,~400 行)

```
mini-harness/
├── agent.py          # Agent Loop:循环驱动器(run() 主入口)
├── llm.py            # LLM 客户端:调 DeepSeek API(OpenAI 兼容格式)
├── session.py        # 会话日志:append + 回放 + 上下文重建
├── tools/
│   ├── __init__.py
│   ├── registry.py   # 工具注册表:名字 → 工具定义
│   ├── guard.py      # 危险拦截:标记危险的工具需要审批
│   └── executor.py   # 执行管道:校验参数 → 跑函数 → 检查结果
├── examples/
│   └── weather_bot.py  # 演示:天气查询机器人(含一个危险工具做演示)
└── tests/
    ├── test_loop.py    # 循环测试
    ├── test_tools.py   # 工具测试
    ├── test_guard.py   # 拦截测试
    └── test_session.py # 日志测试
```

## 7. 分步实施计划(每步能跑、能验证)

### 第 1 步:让机器人会干活(~100 行,半天)

只写 `llm.py` + `agent.py` + 最简 `session.py`(先存内存列表,不落盘)。
循环跑通:任务进去,AI 自己决定调工具,完成,输出。

✅ 验证:跑通"帮我查天气并给建议"(工具先写死返回假数据,不真联网)

**这一步先不碰 guard、不碰文件日志**——先让循环转起来。

### 第 2 步:给它安"手"(~100 行,半天)

写 `tools/registry.py` + `tools/executor.py`。工具注册表 + pydantic 参数校验 + 结果检查。

✅ 验证:AI 传错参数类型 → 系统拦下报错,不崩;未知工具 → 清晰报错

### 第 3 步:给它"本子"(~80 行,半天)

`session.py` 落盘 JSONL:每步追加,重启恢复,回放重建上下文。

✅ 验证:跑完任务打开日志文件能从头看到尾;关掉重开,AI 记得之前说了啥

### 第 4 步:上规矩 + 演示(半天)

`tools/guard.py`:危险工具(如 delete_file)默认拒绝或要审批。写测试钉死规则。连真实 DeepSeek API 跑一个真实任务,录屏。

✅ 最终验证:任务"整理某文件夹的笔记,按主题归类"——机器人自己规划、调工具、干完,全程可回放。录屏 = 面试落地证据

## 9. 面试怎么讲这个项目(30 秒版)

> "我把 DeepSeek 开源的 Agent 框架 DSH 完整分析了一遍,然后自己用 Python 写了个缩小版 Mini-Harness——复刻了它的三个核心架构:Agent 循环、工具执行管道(危险操作拦截、参数校验)、事件溯源会话日志(每一步只追加、可完整回放)。这是我自己写的一个 Agent 框架的核。"

**追问弹药**:
- "为什么日志只追加?" → 历史不可变,出错能回放定位,AI 看到的上下文从日志重建,单一真相源
- "guard 为什么只能拒绝不能放行?" → 安全只能收紧;能放行 = 被绕过的口子
- "为什么参数要校验?" → LLM 输出不可信,可能传错类型、可能试图调危险工具,先验后跑
